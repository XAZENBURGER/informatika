# ПОШАГОВОЕ РУКОВОДСТВО — Лабораторная «Командная строка и элементарная алгоритмизация»

Все исходники лежат в папке `src/`, тестовые файлы — в `testdata/`.
Каждый код снабжён подробными комментариями «для новичка».

---

## ШАГ 1. Создаём проект в Visual Studio (задание 1)

1. Откройте **Visual Studio** → *Создать проект* → найдите **«Консольное приложение»**
   (Console App, C++) → *Далее*.
2. Имя проекта: `lab` → *Создать*.
3. VS сама создаст файл `lab.cpp` с заготовкой кода. Удалите всё из него и
   вставьте содержимое файла `src/01_lab.cpp`.
4. Нажмите **Ctrl+Shift+B** («Собрать решение»). Внизу появится
   *«Сборка успешно завершена»*.

---

## ШАГ 2. Находим lab.exe и открываем там терминал (задание 2)

Исполняемый файл обычно лежит здесь:

```
lab\lab\x64\Debug\lab.exe        (если платформа x64, конфигурация Debug)
```

Как открыть командную строку прямо в этой папке:
- В Проводнике перейдите в папку с `lab.exe`,
- кликните в адресную строку Проводника, напишите `cmd` и нажмите Enter —
  откроется чёрное окно, где текущая папка уже та, что нужна.

(Альтернатива: в Visual Studio меню *Проект → Свойства → Отладка →
«Рабочий каталог»*, либо вкладка *Отображение → Терминал*.)

---

## ШАГ 3. Запуск и автодополнение Tab (задание 3)

В окне cmd наберите:

```
lab
```

и нажмите Enter. Программа напечатает свой текст.

Теперь наберите только букву `l` и нажмите **Tab** — терминал сам
подставит `lab.exe` (перебирает файлы, начинающиеся на `l`). Это удобно
для длинных имён.

---

## ШАГ 4. Перенаправление вывода `>` (задание 4)

```
lab > o.txt
```

Текста в терминале **не будет** — он записался в файл `o.txt` рядом с `lab.exe`.
Проверьте:

```
type o.txt
```

`>` означает: «весь стандартный вывод программы (`cout`) пиши не на экран, а в файл».

---

## ШАГ 5. Опасность `>` — перезапись (задание 5)

1. Измените текст в `main()` (например, на `"Novaya versiya"`), **пересоберите** проект.
2. Снова выполните `lab > o.txt`, затем `type o.txt`.
   Старого текста нет — `>` **стирает** файл перед записью без предупреждения!
3. Чтобы повторить команду, не набирая заново: нажмите **↑ (стрелку вверх)**
   несколько раз — терминал листает историю команд. Затем Enter.

## ШАГ 6. Дописывание `>>` (задание 6)

```
lab >> o.txt
type o.txt
```

Теперь новый вывод **дописан** после старого содержимого (в файле две копии).

## ШАГ 7. Код из задания — удаление повторов СИМВОЛОВ (задание 7)

**Ответ:** код читает поток посимвольно и выводит его, схлопывая серии
одинаковых подряд идущих символов в один символ.
`"aaabbbcccd"` → `"abcd"`. Повторы, разделённые другими символами
(`"abaca"`), останутся — код сравнивает только с ПРЕДЫДУЩИМ символом.

Код с построчным объяснением: `src/02_dedup_chars.cpp`.

Проверка: соберите как `dedup.exe` и выполните в папке с тестовым файлом:

```
dedup < chars.txt
```

Мой прогон (файл содержал `aaabbbcccd ee ddaa` + `hello world`):

```
abcd e da
helo world
```

Видно: `ll` в hello схлопнулось в `l`, серии `aaa/bbb/ccc` — в одиночные.

## ШАГ 8. `cin >>` против `getline` (задание 8)

**Ответ:** разница в том, где останавливается чтение:
- `cin >> name` читает **одно слово** (останавливается на пробеле);
- `getline(cin, name)` читает **всю строку до Enter**, пробелы включительно.

Код обоих вариантов с объяснениями: `src/03_str_compare.cpp`.

Реальный прогон при вводе `Ivan Petrov Sidorov`:

```
Вариант >>:       Greetings, Ivan
Вариант getline:  Greetings, Ivan Petrov Sidorov
```

Бонус для понимания: `getline` возвращает сам поток, поэтому её можно писать
прямо в условии цикла: `while (getline(cin, line)) { ... }` — цикл крутится,
пока читаются строки, и завершается на конце файла.

## ШАГ 9. unique.exe — удаление повторов СТРОК (задание 9)

Код: `src/04_unique.cpp`. Соберите проект и **переименуйте** `lab.exe`
(или переименуйте выходной файл в свойствах проекта) в `unique.exe`.

Проверка через перенаправление:

```
unique < fruits.txt > result.txt
type result.txt
```

Файл `fruits.txt`: `apple, banana, banana, cherry, apple, date` (каждая строка с новой).

Результат БЕЗ сортировки:

```
apple
banana
cherry
apple      ← второй apple остался! Он не соседний дубликат
date
```

Программа убирает только **подряд идущие** повторы (как и требовалось).

## ШАГ 10. Пайп: `sort | unique` (задание 10)

Запись `A | B` — вывод программы A подаётся на ввод программе B.
`sort` сортирует строки по алфавиту; после этого ВСЕ одинаковые строки
стоят рядом, и `unique` уничтожает их полностью:

```
sort fruits.txt | unique > nodups.txt
type nodups.txt
```

Мой прогон:

```
apple
banana
cherry
date          ← оба дубля исчезли
```

Просмотр по экранам: `sort fruits.txt | unique | more`

## ШАГ 11. Коды возврата и связки `&&` / `||` (задание 11)

Любая программа возвращает число из `main()`: **0 = успех**, другое = ошибка.
- `команда1 && команда2` — команда2 выполнится ТОЛЬКО если команда1 успешна;
- `команда1 || команда2` — команда2 выполнится ТОЛЬКО если команда1 НЕУСПЕШНА;
- `команда && echo OK || echo FAIL` — сообщение об успехе/неудаче.

В Windows код последней команды можно посмотреть так: `echo %errorlevel%`.

## ШАГ 12. dupcheck.exe — поиск дублей через код возврата (задание 12)

Код: `src/05_dupcheck.cpp`. Возвращает **1**, если две подряд идущие строки
совпали, иначе **0**.

Вызов из условия (работает в cmd):

```
sort fruits.txt | dupcheck && echo Duplikatov_net || echo Est_duplikaty
```

Мои прогоны:
- файл `fruits.txt` (есть дубли) → печатает `Duplicate found: "apple"` и
  выдаёт `Est_duplikaty` (код возврата 1);
- файл `nodups.txt` (дублей нет) → выдаёт `Duplikatov_net` (код возврата 0).

Почему нужен именно `sort` перед `dupcheck`: после сортировки любые равные
строки становятся соседями, и проверки соседей достаточно.

## ШАГ 13. Аналог команды more (задание 13)

Код: `src/06_mymore.cpp`. Печатает по 24 строки, затем ждёт клавишу:
любая — продолжить, `q` — выйти. Использует `_getch()` из `<conio.h>`
(есть только в MS Visual Studio), чтобы реагировать на клавишу без Enter.
В коде это спрятано под `#ifdef _MSC_VER`, поэтому файл компилируется и
в других компиляторах (там пауза будет работать через Enter).

Проверка:

```
sort fruits.txt | mymore
```

## Как собрать каждый файл в Visual Studio
Самый простой способ: создавайте отдельный консольный проект под каждый
файл (Project → Add → Existing Item → нужный .cpp), либо меняйте содержимое
единственного `lab.cpp`. Имя exe задаётся в:
*Проект → Свойства → Общие → Имя выходного файла* (например `unique.exe`).
