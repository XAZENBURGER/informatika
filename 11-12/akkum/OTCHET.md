## Задание 1 (Вариант 3)

### Условие (переписано из методички)

> **Вариант 3.** Сумма модулей чисел, не превосходящих по модулю единицу.

То есть среди всех введенных чисел нужно отобрать те, для которых |x| ≤ 1, взять модуль каждого такого числа и сложить их. Если ни одно число не подошло — вывести 0.

### Код программы (`src/v3.cpp`)

```cpp
// Вариант 3. Сумма модулей чисел, не превосходящих по модулю единицу.
// Предикат: |x| <= 1. Действие: sum += fabs(x). Если таких чисел нет — 0.
#include <iostream>
#include <cmath>            // fabs — модуль числа
using namespace std;

int main() {
    double sum = 0;         // аккумулятор: начальное значение 0

    // Цикл ввода: читаем числа из потока cin, пока чтение успешно.
    for (double x; cin >> x; )
        if (fabs(x) <= 1)       // предикат: число не превосходит 1 по модулю
            sum += fabs(x);     // аккумуляция: добавляем модуль числа к сумме

    cout << sum << endl;    // вывод результата
    return 0;
}
```

### Пояснение по строчкам (для новичка)

- `#include <iostream>` — подключаем библиотеку ввода-вывода (`cin`, `cout`).
- `#include <cmath>` — математическая библиотека; оттуда берём функцию `fabs(a)` — «absolute value floating», модуль числа: `fabs(-0.25)` даст `0.25`.
- `double sum = 0;` — заводим **аккумулятор** (коробку, в которую копим результат). Ставим туда 0, потому что сумма пустого набора чисел равна нулю — это и есть требуемый ответ «если подходящих чисел не будет».
- `for (double x; cin >> x; )` — нестандартная запись цикла `for`, но очень удобная для чтения данных:
  - `double x;` — перед каждой итерацией создаётся переменная `x`;
  - `cin >> x;` — пытаемся считать очередное число. Оператор `>>` возвращает поток, а поток в условии — это «успешно ли прочиталось?». Пока в потоке есть числа — цикл продолжается; когда файл закончился (или пользователь нажал Ctrl+Z в консоли) — условие ложно, цикл завершается;
  - третья часть цикла (шаг) пуста — счётчик нам не нужен, мы идём по данным.
- `if (fabs(x) <= 1)` — **предикат**: фильтруем числа, оставляя те, чей модуль не больше единицы (то есть числа из промежутка [−1; 1]).
- `sum += fabs(x);` — **аккумуляция**: прибавляем к накопленному модуль подходящего числа. Числа вне промежутка просто игнорируются.
- `cout << sum << endl;` — выводим итог в стандартный поток вывода.

### Проверка (команды для cmd)

```
v3.exe < data.txt
v3.exe < nomatch.txt
```

Ожидаемый результат:
- `data.txt`: подходят 0.5, 1, −0.25, 0.75, −1 → сумма модулей 0.5 + 1 + 0.25 + 0.75 + 1 = **3.5**;
- `nomatch.txt`: ни одно число не подходит → **0**.

Фактический вывод (проверено): `3.5` и `0` — совпадает с ручным расчётом.

## Задание 2 (Вариант 6)

### Условие (переписано из методички)

> **Вариант 6.** Корень квадратный из суммы квадратов чисел, не превосходящих по модулю единицу.

Среди введенных чисел отбираем те, для которых |x| ≤ 1, суммируем их квадраты, а из полученной суммы извлекаем квадратный корень. Пустое множество даёт сумму 0 и корень √0 = 0 — требуемый «нуль по умолчанию» получается автоматически.

### Код программы (`src/v6.cpp`)

```cpp
// Вариант 6. Корень квадратный из суммы квадратов чисел,
// не превосходящих по модулю единицу.
// Предикат: |x| <= 1. Действие: sum += x*x. Итог: sqrt(sum). Пусто -> 0.
#include <iostream>
#include <cmath>            // fabs, sqrt
using namespace std;

int main() {
    double sum = 0;         // аккумулятор суммы квадратов

    for (double x; cin >> x; )
        if (fabs(x) <= 1)       // предикат: |x| <= 1
            sum += x * x;       // аккумуляция: прибавляем квадрат числа

    cout << sqrt(sum) << endl;  // результат: корень из накопленной суммы
    return 0;
}
```

### Пояснение по строчкам

- Структура та же, что в варианте 3, меняются только два места:
- `sum += x * x;` — теперь в аккумулятор кладём **квадрат** числа. Квадрат любого числа неотрицателен, поэтому `sum` никогда не станет отрицательной — взятие корня безопасно.
- `sqrt(sum)` — функция квадратного корня из `<cmath>`. Применяем её уже **после** цикла, один раз к итогу, а не к каждому числу.
- Если подходящих чисел не было вообще: `sum` осталась 0 → `sqrt(0)` = 0 → программа печатает `0`, как требует критерий №3.

### Проверка

```
v6.exe < data.txt
v6.exe < nomatch.txt
```

Ожидаемый результат:
- `data.txt`: подходят 0.5, 1, −0.25, 0.75, −1 → сумма квадратов 0.25 + 1 + 0.0625 + 0.5625 + 1 = 2.875 → √2.875 ≈ **1.69558**;
- `nomatch.txt`: **0**.

Фактический вывод (проверено): `1.69558` и `0`.

`[СКРИНШОТ: терминал с командами v6.exe < data.txt и v6.exe < nomatch.txt и ответами 1.69558 / 0]`

## Задание 3 (Вариант 9)

### Условие (переписано из методички)

> **Вариант 9.** Сумма синусов чисел, не превосходящих по модулю π.

Отбираем введенные числа x с |x| ≤ π, считаем sin(x) для каждого и складываем результаты. Если подходящих чисел нет — выводим 0.

### Код программы (`src/v9.cpp`)

```cpp
// Вариант 9. Сумма синусов чисел, не превосходящих по модулю pi.
// Предикат: |x| <= pi. Действие: sum += sin(x). Если таких чисел нет — 0.
#include <iostream>
#include <cmath>            // fabs, sin; M_PI — константа пи
using namespace std;

int main() {
    double sum = 0;         // аккумулятор суммы синусов

    for (double x; cin >> x; )
        if (fabs(x) <= M_PI)    // предикат: |x| <= pi
            sum += sin(x);      // аккумуляция: прибавляем sin(x)

    cout << sum << endl;    // вывод результата
    return 0;
}
```

### Пояснение по строчкам

- `M_PI` — готовая константа «π ≈ 3.14159...», поставляется в `<cmath>` при компиляции в Visual Studio (там по умолчанию включён режим MSVC-расширений). Аргументы тригонометрических функций в C++ задаются **в радианах**, поэтому сравнение с π — это сравнение угла с половиной оборота.
- `sin(x)` — синус числа x (в радианах). Например, `sin(3.14)` ≈ 0.00159 (ведь 3.14 чуть меньше π, а sin π = 0), `sin(0.5)` ≈ 0.4794.
- Синусы бывают отрицательными (например, sin(−1) ≈ −0.84), поэтому сумма может уменьшаться — это нормально, аккумулятор работает и с отрицательными приращениями.
- Начальное значение 0 снова обеспечивает «нуль» при отсутствии подходящих чисел.

### Проверка

```
v9.exe < data.txt
v9.exe < nomatch.txt
```

Ожидаемый результат для `data.txt`: из чисел `0.5 -2 1 -0.25 3 0.75 1.5 -1 2.0 3.14 -3.15` условию |x| ≤ π (π ≈ 3.14159) не удовлетворяет только −3.15; остальные 10 чисел подходят. Сумма их синусов ≈ **2.05387** (сверено программно). Для `nomatch.txt` (все числа по модулю больше π) — **0**.

Фактический вывод (проверено): `2.05387` и `0`.

`[СКРИНШОТ: терминал с командами v9.exe < data.txt и v9.exe < nomatch.txt и ответами 2.05387 / 0]`

## Микровывод

Все три варианты решены одной и той же проверенной схемой «цикл ввода → предикат → аккумуляция → вывод»:

1. **Цикл `for (double x; cin >> x; )`** универсален: он сам останавливается на конце файла (при перенаправлении `< file.txt`) или на признаке конца ввода (Ctrl+Z + Enter в консоли), поэтому один и тот же exe работает и «вручную», и с файлом — что и требовала навигация прошлой лабораторной по командной строке.
2. **Разница между вариантами только в двух строчках** — предикате (`|x| ≤ 1`, `|x| ≤ 1`, `|x| ≤ π`) и операции аккумуляции (`+|x|`, `+x²`, `+sin x`). Это показывает силу шаблона: меняя фильтр и «коробку», можно решить десятки задач на выборку.
3. **Нуль «по умолчанию»** получился бесплатно во всех задачах благодаря начальному значению аккумулятора 0 (а в варианте 6 ещё и потому, что √0 = 0). В задачах, где нейтральное значение другое (например, произведение — 1), пришлось бы инициализировать иначе — здесь этого не потребовалось.
4. Результаты сверены с ручным расчётом: 3.5, 1.69558 (=√2.875) и 2.05387 для тестового файла; 0 — для файла без подходящих чисел. Все критерии полноты (корректный цикл ввода, предикат внутри цикла, вывод в `cout`, нуль при пустом множестве) выполнены.
