# Почему cmd «не находит» lab.exe и как это починить (задания 3–6)

## Диагноз: две разные причины, обе решаются за минуту

### Причина №1 (самая частая): ты НЕ в той папке
Командная строка ищет программу **только в текущей папке** (в Windows
текущую папку в PATH не добавляют — в отличие от Linux/macOS).

Как проверить, где ты сейчас:
```
cd
```
cmd напечатает что-то вроде `C:\Users\you`. Если там нет lab.exe — естественно,
«не найдено».

### Причина №2: файл называется не lab.exe
Visual Studio называет exe по имени **проекта**: `Project1.exe`, `ConsoleApplication1.exe`...
В методичке предполагается, что файл называется lab.exe. Если он у тебя Project1.exe —
команда `lab` не сработает никогда.

---

## Решение А: сесть в правильную папку (правильный способ по методичке)

1. **Где лежит exe?** В Visual Studio: меню «Отладка» → «Начать отладку» (F5),
   в нижнем окне «Вывод» первой строкой печатается путь, типа:
   `...Проект\Проект\bin\Debug\Project1.exe`
   (в новых VS: Обозреватель решений → правый клик по проекту →
   «Открыть папку в проводнике»).

2. **Открой cmd именно там.** Самый простой трюк:
   - Проводник → зайди в папку с lab.exe
   - Кликни в **адресную строку** проводника, напиши `cmd` и жми Enter.
   - Откроется чёрное окно, и в его заголовке будет эта папка. Всё, ты дома.

3. **Переименуй exe в lab.exe** (раз в задании имя такое):
   ```
   ren Project1.exe lab.exe
   ```
   или просто F2 в проводнике.

4. Теперь работают все команды методички:
   ```
   lab                Tab-перебор по "l" тоже заработает
   lab >o.txt
   lab >>o.txt
   dir o.txt          убедиться, что файл появился
   type o.txt         посмотреть содержимое
   ```

⚠️ Важно: после каждой пересборки проекта (F5) VS заново создаёт
`Project1.exe`. Просто снова выполни `ren Project1.exe lab.exe`
или переименуй проект в VS сразу: Правый клик по решению → «Переименовать» → `lab`.
Тогда exe всегда будет `lab.exe` и проблем не будет.

---

## Решение Б: запускаться из любой папки по полному/относительному пути

Если лень каждый раз переходить — пиши путь к exe явно:
```
"C:\Полный\Путь\До\Папки\lab.exe" >o.txt
```
Кавычки обязательны, если в пути есть пробелы (у VS они есть почти всегда:
`C:\Users\Имя\source\repos\Project1\Project1\bin\Debug`).

Минус: вывод `>o.txt` тогда пишется в **текущую** папку cmd, а не в папку exe.
Это нормально, просто знай.

## Быстрая самодиагностика (по одной команде)

| Команда | Что покажет |
|---|---|
| `cd` | в какой ты папке |
| `dir *.exe` | какие программы тут лежат; если пусто — ты не в bin\Debug |
| `where lab` | нашла ли система lab.exe вообще |
| `dir /s ..\..\..\lab.exe 2>nul` | поиск lab.exe выше по дереву проекта |

Если `dir *.exe` показывает `Project1.exe` — см. пункт «переименовать».
Если `dir *.exe` пустой — см. пункт «сесть в правильную папку».

## Про Tab (задание 3)
Tab работает только для файлов **в текущей папке**. Набери `l` + Tab —
если в этой папке есть lab.exe, cmd допишет имя сам. Не дописывает —
значит снова не та папка (проверь `cd`).

## Итого чек-лист на 1 минуту
1. Проводник → папка с exe → в адресной строке `cmd` + Enter
2. `ren Project1.exe lab.exe` (если нужно)
3. `lab` + Enter → текст в консоли ✔
4. `lab >o.txt`, `type o.txt`, `lab >>o.txt`, `type o.txt` ✔
